    Structure:

    ```typescript
    /**
     * Phase 2 verification harness (TAPI-11).
     *
     * Runs the three Tableau service smoke scripts sequentially against the
     * sandbox (or in cold-boot mode when .env is empty) plus the offline
     * pulseService.empty.test.ts which guards TAPI-10 graceful-degradation.
     *
     * Exit 0 only if every child exits 0.
     *
     * Run with: pnpm --filter @aperture/backend smoke:phase2
     */
    import { spawn } from 'node:child_process';
    import { fileURLToPath } from 'node:url';
    import { dirname, resolve } from 'node:path';

    const __filename = fileURLToPath(import.meta.url);
    const __dirname = dirname(__filename);

    interface Step {
      readonly label: string;
      readonly script: string;   // path relative to this file's directory
      readonly requirement: string;
    }

    const STEPS: readonly Step[] = [
      { label: 'Metadata API',    script: './metadataService.smoke.ts', requirement: 'TAPI-01/02' },
      { label: 'VizQL Data Svc',  script: './vizqlService.smoke.ts',    requirement: 'TAPI-03/04/05/06' },
      { label: 'Pulse REST',      script: './pulseService.smoke.ts',    requirement: 'TAPI-07/08/09' },
      { label: 'Pulse empty (offline)', script: './pulseService.empty.test.ts', requirement: 'TAPI-10' },
    ];

    function runStep(step: Step): Promise<number> {
      return new Promise((resolvePromise) => {
        const fullPath = resolve(__dirname, step.script);
        console.log(`\n================================================================`);
        console.log(`[phase2] Running ${step.label} (${step.requirement})`);
        console.log(`[phase2] Script: ${step.script}`);
        console.log(`================================================================`);
        // Pass through child argv after the harness's own args so callers can
        // forward --datasource / --workbook / --field flags to every child.
        const childArgs = process.argv.slice(2);
        const child = spawn('npx', ['tsx', fullPath, ...childArgs], {
          stdio: 'inherit',
          env: process.env,
        });
        child.on('exit', (code) => resolvePromise(code ?? 1));
        child.on('error', (err) => {
          console.error(`[phase2] Failed to spawn ${step.label}:`, err);
          resolvePromise(1);
        });
      });
    }

    async function main(): Promise<void> {
      const results: Array<{ step: Step; code: number }> = [];
      for (const step of STEPS) {
        const code = await runStep(step);
        results.push({ step, code });
        if (code !== 0) {
          // Continue running remaining steps so the user sees the full picture,
          // but mark overall as failed.
          console.log(`[phase2] ${step.label} exited with code ${code}`);
        }
      }

      console.log(`\n================================================================`);
      console.log(`[phase2] SUMMARY`);
      console.log(`================================================================`);
      let allPass = true;
      for (const { step, code } of results) {
        const status = code === 0 ? 'PASS' : 'FAIL';
        if (code !== 0) allPass = false;
        console.log(`[phase2]   ${status}  ${step.label.padEnd(26)} (${step.requirement})`);
      }
      console.log(`================================================================`);
      if (allPass) {
        console.log(`[phase2] ALL GREEN — Phase 2 TAPI-01..TAPI-11 verified (TAPI-11)`);
        process.exit(0);
      } else {
        console.error(`[phase2] FAILED — one or more services did not exit 0`);
        process.exit(1);
      }
    }

    main().catch((err) => {
      console.error('[phase2] Fatal harness error:', err);
      process.exit(1);
    });
    ```

    Notes:
    - Use `spawn('npx', ['tsx', ...])` (not `exec`) so child output streams live
      into the terminal — matches the feel of `smoke:auth` which streams Pino
      output directly.
    - The harness forwards `process.argv.slice(2)` to every child so a user can
      run `pnpm --filter @aperture/backend smoke:phase2 -- --datasource <luid>`
      and have every service get the same LUID. Children that don't understand
      a flag simply ignore it (they already handle missing flags as cold-boot).
    - The pulseService.empty.test.ts child does NOT need credentials — it runs
      offline and will pass regardless of the .env state. This is important:
      even if all three live smokes cold-boot, the empty-pulse test provides
      hard TAPI-10 regression coverage in the harness output.
    - Do NOT print `process.env`. Do NOT log tokens.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| harness → child processes | Arguments forwarded to spawned tsx children. Low trust boundary since callers are developers on their own machine, but still needs basic hygiene. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05-01 | Tampering (T) | Script reordering or deletion in package.json | mitigate | Task 1 acceptance criteria grep-verify every Phase 1 script (`dev`, `build`, `start`, `typecheck`, `smoke:auth`) is still present after the edit, preventing accidental regression. |
| T-02-05-02 | Elevation / Injection (E) | User-supplied args forwarded to child spawn | mitigate | The harness uses `spawn('npx', ['tsx', fullPath, ...args])` with an argv array — no shell interpolation. Users can pass `--datasource <luid>`, but there is no shell to inject into (`spawn` without `shell: true`). |
| T-02-05-03 | Information disclosure (I) | Children leaking tokens into aggregated output | accept | The child scripts themselves are responsible for redaction (enforced in 02-02/03/04 acceptance criteria). This harness uses `stdio: 'inherit'` and adds no logging of its own beyond step labels. |
| T-02-05-04 | Denial of service (D) | One slow child blocking the harness forever | accept | Phase 2 is dev-facing; a stuck child is developer-visible and they can Ctrl-C. Not worth adding timeouts that could create false failures on slow networks. |
| T-02-05-05 | Repudiation (R) | No persistent log of phase2 runs | accept | Aperture v1 is single-user; stdout is the log. |

No high-severity unmitigated threats.
</threat_model>
