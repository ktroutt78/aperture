Tableau Metadata API endpoint (REST API 3.19+):
- POST `{serverUrl}/api/metadata/graphql`
- Body: `{ "query": "...", "variables": { ... } }`
- Response: `{ "data": { ... }, "errors"?: [...] }`
- Auth: X-Tableau-Auth (handled automatically by tableauFetch)

- Uses `console.log('[smoke] ...')` prefix

    ```typescript
    export async function fetchSchemaByDatasourceLuids(datasourceLuids: readonly string[]): Promise<SchemaContext>;
    ```
    - Validate every LUID against `/^[a-f0-9-]{36}$/i` — throw MetadataServiceError on any mismatch (SSRF/GraphQL-injection defense)
    - Use this GraphQL query EXACTLY (do NOT interpolate LUIDs into the string — pass them via variables):
      ```graphql
      query FieldsForDatasources($luids: [String!]!) {
        publishedDatasources(filter: { luidWithin: $luids }) {
          luid
          fields {
            name
            description
            upstreamColumns { name fullyQualifiedName }
            ... on ColumnField { dataType }
            ... on CalculatedField { dataType }
          }
        }
      }
      ```
      Map response as follows into `SchemaField`:
      - `name`: `field.name` (string, required)
      - `caption`: `field.name` (Metadata API's `name` carries the user-facing caption for published datasources; if a future schema exposes a distinct caption field, swap here)
      - `dataType`: `field.dataType ?? 'UNKNOWN'`
      - `description`: `field.description ?? ''`
      - `upstreamLineage`: `(field.upstreamColumns ?? []).map(c => c.fullyQualifiedName ?? c.name).filter(Boolean)` — coerced to readonly string array
    - Build the return:
      ```typescript
      const datasources: Record<string, SchemaField[]> = {};
      for (const ds of data.publishedDatasources ?? []) {
        datasources[ds.luid] = (ds.fields ?? []).map(toSchemaField);
      }
      return { datasources };
      ```
    - Log at info level: `{ requested: datasourceLuids.length, returned: Object.keys(datasources).length, totalFields: <sum> }`. Do NOT log the field contents.

    **Exported function 2 — TAPI-02:**
    ```typescript
    export async function fetchWorkbookMetadata(workbookLuid: string): Promise<SchemaContext>;
    ```
    - Validate `workbookLuid` against the same UUID regex; throw on mismatch.
    - GraphQL query EXACTLY:
      ```graphql
      query WorkbookMeta($luid: String!) {
        workbooks(filter: { luid: $luid }) {
          luid
          name
          sheets {
            ... on Worksheet {
              luid
              name
              upstreamDatasources { luid }
            }
          }
        }
      }
      ```
    - Map result:
      ```typescript
      const wb = (data.workbooks ?? [])[0];
      if (!wb) return { datasources: {} };
      const workbook: WorkbookMetadata = {
        luid: wb.luid,
        name: wb.name,
        worksheets: (wb.sheets ?? []).map((s: any) => ({
          luid: s.luid,
          name: s.name,
          connectedDatasourceLuids: (s.upstreamDatasources ?? []).map((d: any) => d.luid),
        })),
      };
      return { datasources: {}, workbook };
      ```
      (The `datasources` object is empty here — downstream Context Assembler will
      call `fetchSchemaByDatasourceLuids` with the collected LUIDs in Phase 3.)

    - Interpolate LUIDs into the GraphQL query string (always use variables)
    - Log the full token, full response body, or raw field data at info level
    - Export mutable state

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend → Tableau Cloud | LUIDs passed from CLI/API callers get embedded in GraphQL queries and URL paths. Untrusted input crosses here. |
| backend ← Tableau Cloud | Response bodies may contain datasource metadata — not PII, but still need size caps. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Information disclosure (S/I) | Session token in logs | mitigate | Service uses `tableauFetch`, which owns `X-Tableau-Auth`. Phase 1 Pino redact paths cover `req.headers["x-tableau-auth"]`. This plan adds no new logging of the token or response body at info level. |
| T-02-02-02 | Tampering (T) / Elevation (E) | GraphQL query injection via LUID parameter | mitigate | All LUIDs pass through a `^[a-f0-9-]{36}$` regex guard BEFORE being sent. They are passed as GraphQL variables, never interpolated into the query string. Grep-verified in acceptance criteria (`\\$\\{.*luid` == 0). |
| T-02-02-03 | Spoofing (S) / SSRF | User-controlled LUIDs concatenated into URLs | mitigate | LUIDs are never concatenated into URLs in this service — the Metadata API endpoint is a fixed constant `/api/metadata/graphql`. LUIDs only appear in POST body variables. |
| T-02-02-04 | Denial of service (D) | Unbounded Metadata API response size | accept | Metadata API responses are bounded by Tableau Cloud's server-side limits (schemas are small — hundreds of fields, not millions). No streaming needed at this layer. If a pathological datasource is discovered in practice, add a response-size guard in a follow-up. |
| T-02-02-05 | Repudiation (R) | No audit log of metadata queries | accept | Aperture v1 is single-user; Tableau Cloud already logs REST calls server-side. Not worth adding. |

No high-severity unmitigated threats.
</threat_model>
